Vos fichiers, d'un appareil à l'autre. Sans détour.

DropForge envoie vos fichiers entre Windows, Android, iOS et n'importe quel navigateur. Sans compte obligatoire, chiffré de bout en bout, et en direct de machine à machine dès que le réseau le permet.

L'application web

Deux chemins, un seul logiciel : l'application web est le plus rapide à essayer ; l'application Windows donne les transferts en arrière-plan, la zone de notification et le démarrage automatique. Les deux se parlent entre elles.

Sans compte obligatoire

Aucune inscription pour transférer. Pas de télémétrie par défaut, pas de fichier conservé sur un serveur : ce qui vous appartient reste chez vous.

Direct dès que possible

Même réseau : le transfert ne sort jamais du réseau local, et rien d'autre que vos deux appareils n'intervient. Entre deux réseaux différents, un canal chiffré est négocié de machine à machine — le serveur ne voit jamais les fichiers — mais cette mise en relation demande un relais que vous hébergez : c'est la feuille de route, pas la promesse du jour.

Chiffré et vérifié

Chiffrement de bout en bout par les bibliothèques du navigateur, intégrité SHA-256 avant tout état « terminé », reprise après coupure, jamais d'écrasement silencieux.

Ce que DropForge fait vraiment

Chaque ligne ci-dessous correspond à du code exécuté à chaque envoi, avec ses tests. Ce qui n'est pas encore fait est dit plus bas, sans arrangement.

Transferts

Tous types de fichiers, sélection multiple, glisser-déposer et dossiers là où le système le permet. File d'attente avec pause, reprise, annulation, réessai et réordonnancement.

Appareils

Découverte sur le réseau local, appairage par code et QR code, connexion manuelle par code de salle, appareils de confiance révocables, favoris avec envoi en une action.

Historique et réglages

Historique cherchable et filtrable, notifications, langue (français et anglais), thème sombre ou clair, dossier de réception, règles de conflit, limites de parallélisme.

Deux coques, une interface

Application Windows (Tauri 2 + Rust) et application web progressive partagent exactement la même interface React/TypeScript : même comportement, mêmes écrans.

Sans réseau

Une fois installée, l'application web fonctionne hors ligne et se sert depuis n'importe quel dossier : utile sur un réseau isolé ou une clé USB.

Le code est ouvert, les limites aussi

Aucune promesse de capacité illimitée, aucune estimation optimiste : le modèle de menace et la matrice des plateformes disent ce qui est protégé — et ce qui ne l'est pas.

Comment la connexion est choisie

Dans l'ordre, la première méthode qui fonctionne réellement. Si aucune ne fonctionne, DropForge le dit clairement au lieu de faire semblant.

  1. Réseau local Les deux appareils sont sur le même réseau : rien ne sort du réseau local. C'est ce qui est prêt aujourd'hui, et une seule commande le met en place : npm run lan.
  2. Direct (WebRTC) Un canal chiffré de bout en bout est négocié avec l'aide d'un serveur de signalisation qui ne voit que de la négociation. Le code est écrit et testé ; il attend un relais que vous hébergez.
  3. Relais aveugle En dernier recours, un serveur relaie des octets déjà chiffrés qu'il ne peut pas lire. Même chose : implémenté et testé, hors de l'interface tant qu'aucun relais n'est déclaré.

Ce qui protège vos fichiers — et ce qui ne les protège pas

La sécurité se raconte mal en une phrase. Voici la version honnête, tirée du modèle de menace du dépôt.

Protégé

Contenu chiffré de bout en bout ; le serveur de signalisation ne voit jamais les fichiers ; aucune clé, aucun secret et aucun contenu de fichier dans les journaux ; appairage vérifiant l'identité cryptographique des appareils, pas seulement leur nom.

Pas protégé

Un appareil compromis par un logiciel malveillant, un réseau qui bloque tout, ou la réception en arrière-plan dans un navigateur mobile. DropForge ne prétend pas résoudre ces cas.

À la maison

Tout est stocké localement : préférences, historique, appareils de confiance. La désinstallation propose de supprimer ces données (case décochée par défaut) et ne touche jamais à vos fichiers reçus.

Construire et contribuer

Node 22 et npm suffisent pour l'application web ; Rust n'est nécessaire que pour l'application Windows.

Lancer le projet

git clone {{REPO_URL}}.git
cd DROPForge && npm install
npm run dev

Vérifier avant de proposer

npm run verify

Typage, contrôle de la configuration Windows et tests : la même commande que la chaîne d'intégration.
